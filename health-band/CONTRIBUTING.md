# 贡献指南 / 提交与评审速查

> 完整规范见 [`docs/03_Git仓库与提交规范.md`](docs/03_Git仓库与提交规范.md)

## 一句话规则

**`main` 永远可跑；功能走 `feature/xxx`；合入走 MR + 至少 1 人评审；提交信息写「动词 + 对象 + 原因」。**

## 提交信息模板

```
<type>: <动词><对象>，<原因/目的>
```

| type | 用途 |
| --- | --- |
| `feat` / `fix` / `docs` / `refactor` / `test` / `chore` / `perf` | 新增 / 修复 / 文档 / 重构 / 测试 / 构建配置 / 性能 |

正例：

```
feat: 增加久坐状态机的稍后提醒，避免连续三次提醒后不再提醒
fix: 修复马达震动期间误计步的问题，因合加速度峰值被 PWM 干扰
docs: 补充 P0 需求规格说明书，使每条需求可被测试用例覆盖
```

反例（禁止）：`update`、`修改`、`111`、空信息、一次提交塞多个不相关改动。

## MR 评审检查清单

- [ ] `idf.py build` 通过，无新增警告
- [ ] 关键路径有日志（含时间戳），异常分支有重试或降级
- [ ] 命名分层合规：`ui/` 无 `i2c_master_`、`driver/` 无 `lv_`、`service/` 不直接操作 GPIO
- [ ] 未提交构建产物 / 密钥 / Wi-Fi 密码明文 / `~$*` 临时文件
- [ ] 若涉及需求，已同步更新 [`docs/04_需求追踪矩阵.md`](docs/04_需求追踪矩阵.md)
- [ ] 若涉及新增选做（PC 大模型健康问答 / RAG / 鼠标映射）：已确认默认关闭或不侵入必做闭环、无公网出流量、回答附来源（见 `docs/00_需求规格说明书.md` §5.2、NFR-11/12）
- [ ] 至少 1 名同组同学 Approve

## 常用命令

```bash
git checkout -b feature/srs
git add docs/00_需求规格说明书.md
git commit -m "docs: 补充 P0 需求规格说明书，使每条需求可被测试用例覆盖"
git checkout main
git merge --no-ff feature/srs -m "Merge MR !1: P0 需求规格说明书"
```

## 分组与评审人

见 [`docs/02_分组与角色分工.md`](docs/02_分组与角色分工.md)。当前以角色代号 A（组长）/ B（硬件）/ C（算法）/ D（界面）占位，提交前由组长替换为真实姓名。

## AI 辅助边界

不把 AI 当数据手册、不把 AI 当测试结论、不把 AI 当责任主体；引用 AI 生成内容在 [`docs/00_需求规格说明书.md`](docs/00_需求规格说明书.md) 附录 B 说明。
