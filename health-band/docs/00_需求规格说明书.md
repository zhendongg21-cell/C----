## 1. 引言

### 1.1 编写目的

建立产品全景，明确「**为谁做、做什么、做到什么程度**」。本文档是 P0 的核心基线：每一条需求都有稳定编号（FR-xx / NFR-xx），编号贯穿概要设计、代码实现与测试用例，使「需求可被测试用例覆盖」这一验收标准可逐条核查。

### 1.2 产品定位与边界

- 产品形态：**腕戴式健康监测终端（手环形态）**，表体 110×70×12 mm、表带 24 mm；采用 4.3 寸 800×480 触摸屏是教学可视化的取舍，靠加宽表带、后移重心、贴肤弧度保证佩戴。
- 核心闭环：**察觉—提醒—反馈**。终端本地完成采集、判定、提醒、记录；断网时提醒仍有效（终端自治），服务端只做异步归档，不参与实时判定。
- 主控 ESP32-S3-WROOM-1 N16R8（双核 240 MHz / 16 MB Flash / 8 MB PSRAM / Wi-Fi + BLE / 原生 USB Serial-JTAG）。
- 技术栈：C++17 / ESP-IDF 5.x / FreeRTOS / LVGL 8.3 / CMake 3.16+；PC 端（选做）Qt 5.15 + SQLite + Qt Charts。
- **边界**：不采集真实姓名、学号、手机号；健康数据仅保存在设备与教师机（实训室局域网），不上传公网；USB-C 5 V 仅供电调试，不配电池、不做充电管理；只用 GY-521 / MAX30102 breakout / TMP117 模块，不焊裸片。

### 1.3 术语与缩略语

| 术语 | 含义 |
| --- | --- |
| 有效活动 | 持续 5 min 窗口内步数 ≥ 30 步，或活动强度达中等以上；排除拿水杯、打字、抖腿等干扰 |
| 久坐阈值 | 连续无有效活动的时长，默认 45 min，可在设置页调整并写入 NVS 掉电保存 |
| 免打扰时段 | 22:00–07:00，暂停提醒但保留计时 |
| 游标（cursor） | 本地记录已成功同步的位置；补传按游标分批进行，服务端按 `(device_id, ts)` 幂等去重 |
| 信号质量 | PPG 窗口的可信度判定；质量不合格时界面明确**不显示数值** |
| P0 / P1 / P2 | 必须完成 / 选做推荐 / 拓展创新（本文档 §4.3） |
| FR / NFR | 功能性需求 / 非功能性需求 |
| UC / T | 用例编号 / 测试用例编号 |

## 3. 业务链路拆解（P0 任务 ②）

### 3.1 五链路总览

```
[运动] IMU 50 Hz 采样 → 零偏校准 + 低通 → ImuFrame 入队
   ↓ (步事件 / 活动强度)
[判定] StepService（合加速度、动态阈值、峰谷对）→ SedentaryService 维护久坐计时与状态机
   ↓ (触发条件满足)
[提醒] 马达 2 s×3 + 全屏弹窗（已起身 / 稍后 10 min / 自动稍后）
   ↓ (状态与聚合数据)
[记录] UI 1 s 节流刷新 + RecordStore 每分钟聚合写 LittleFS，环形缓冲 ≥ 7 天
   ↓ (联网时按游标)
[同步] 每 5 min 尝试 Wi-Fi → AUTH → SYNC 分批补传 → ACK → 更新游标 → 关 Wi-Fi
   ↓ (选做·新增，仅在同步完成后于 PC 侧展开，不反向侵入上面五链路)
[问答] PC 归档数据 → 本地索引 → RAG 检索 Top-K 片段 → 拼装 Prompt → 本地大模型 → 回答 + 来源标注
[鼠标] 手环 IMU 手势 / 按键 → BLE HID / 自定义协议 → PC 端驱动 → 鼠标移动 / 点击（默认关）
```

### 3.2 逐链路规约

| 链路 | 触发 / 输入 | 处理 | 输出 | 失败处理 | 承接需求 |
| --- | --- | --- | --- | --- | --- |
| **① 运动** | 上电后 FreeRTOS 任务以 50 Hz 读取 MPU6050 加速度与角速度 | 零偏校准、低通滤波、组装 `ImuFrame` 入队；时间戳单调递增 | 步数、步频、活动强度 | I2C 异常重试并记录日志；丢样率 < 0.1% | FR-01, FR-02, FR-03, NFR-01 |
| **② 判定** | 订阅步事件与活动强度 | StepService 输出步事件；SedentaryService 按状态机判断「佩戴中 + 非免打扰 + 连续 45 min 无有效活动」 | 进入 `Sitting` / `Alerting` 等状态 | 摘腕 → `WearOff` 停止计时并保存状态；22:00–07:00 → `Quiet` 暂停提醒仅计时 | FR-04, NFR-02 |
| **③ 提醒** | 计时达阈值 | 马达 PWM 4 kHz「2 s 震动 / 1 s 间隔」重复 3 次 + 全屏弹窗（遮罩 60% 黑） | 「已起身」/「稍后 10 min」/ 60 s 无操作自动稍后 | 最多 3 次稍后；走 30 步立即复位；弹窗未处理不许切页 | FR-05, NFR-02 |
| **④ 记录** | 每分钟定时聚合 | UI 以 1 s 节流刷新；RecordStore 按 16 字节小端格式写 LittleFS，NVS 保存游标与设置 | 分钟记录、7 天环形缓冲、掉电不丢设置 | 写入中掉电重启文件可读、游标不超前 | FR-06, FR-07, FR-08, FR-13, NFR-05 |
| **⑤ 同步**（选做） | 每 5 min 或联网事件 | AUTH → 带游标 SYNC（JSON Lines）→ 服务端按 `(device_id, ts)` 幂等入库 → ACK 返回 `nextCursor` | 补传完成，更新本地游标后关 Wi-Fi | 断网不丢数据；ACK 丢失重发旧批次仍接受并去重 | FR-14, FR-15, NFR-08 |

### 3.3 链路设计三要点

1. **采集与算法分离**：用队列削峰，采样任务只负责入队，算法任务独立消费。
2. **跨任务传值不传指针**：`ImuFrame` 按值传递，避免生命周期与竞态问题。
3. **UI 必须节流**：1 s 刷新一次，禁止每帧刷全屏，保证 ≥ 25 fps。

采样率取 50 Hz 的依据：实测对比 25 / 50 / 100 Hz，50 Hz 可覆盖 0.5–5 Hz 步态主频且 CPU 不过载。

### 3.4 新增选做链路（用户追加，挂在「同步」之后）

| 选做链路 | 触发 / 输入 | 处理 | 输出 | 失败处理 | 承接需求 |
| --- | --- | --- | --- | --- | --- |
| **⑥ 健康问答** | PC 端已有归档数据，用户用自然语言提问 | 从 `records`/`events` 建索引 → RAG 检索 Top-K → 拼装 Prompt → 送本地大模型 → 回答附来源 | 回答 + 检索来源时间段 + 「教学演示，非医疗建议」 | 无数据 → 提示「暂无可检索数据」；模型不可用 → 明确报错不编造；抓包确保无公网出流量 | FR-19, FR-20, NFR-11 |
| **⑦ 鼠标映射** | 设置页二次确认开启「鼠标映射」 | 手环 IMU 手势 / 按键 → BLE HID 或自定义协议 → PC 端驱动 → 鼠标事件 | 光标移动 / 点击 | 一键断开、超时自动断开；开启期间跑 T-01/T-02 结果不变 | FR-21, NFR-12 |

> 两条新增链路**只在 PC 侧或手环→PC 侧**展开，均不修改「运动—判定—提醒—记录」前四链路；这是把它们列为选做且不冲击四条底线的原因。

| 跌倒检测 | 四阶段判定、15 s 倒计时可取消 | 选做 | FR-12 |

| **基于 PC 端数据的 RAG 检索** | 检索语料来自 PC 端已归档的 `records`/`events` 数据，先检索 Top-K 片段再拼装 Prompt，全程不出实训室局域网 | **选做（新增）** | 用户新增需求；FR-20 |
| **手环操控鼠标** | 手环 IMU 手势 / 按键经 BLE HID 或自定义协议驱动 PC 鼠标移动与点击；默认关闭、需二次确认 | **选做（新增）** | 用户新增需求；FR-21 |

> 三项新增选做的**共同前置**：Wi-Fi 同步 + PC 管理端归档（FR-14 / FR-15）。没有归档数据，RAG 无可检索语料，健康问答与鼠标通道均无从启动；但它们均为选做，裁剪其中任何一项都不影响必做闭环与四条底线（见 §4.2、§4.3）。

### 4.2 明确不做（Out of Scope）

- 电池供电、充电管理、续航优化（本期为 USB-C 供电教学原型）。
- 摄像头/影像、蜂窝网络、蓝牙音频、手机 App 生态适配。
- 医疗器械认证、临床精度、真实用户身份信息与公网服务。
- 睡眠分期、热量医学级估算等需临床验证的算法。
- 三项新增选做的边界：大模型**不上传公网、不采集真实身份、不作医疗诊断**；RAG 语料**仅限 PC 端已归档的本项目数据**，不接入外部知识库；手环鼠标**不自研驱动内核、不改 PC 系统设置**，且默认关闭。

> 上述「不做」直接回应痛点 W-01/W-08 与 W-06：把平台互通与生态适配的复杂度**移出本期边界**，用「终端自治 + 可选只读归档」保证必做功能不依赖任何外部生态即可完整工作。新增三项选做同样遵循此原则——它们挂在「可选只读归档」之后，不反向侵入必做闭环。

### 4.3 优先级定义

| 标记 | 含义 | 验收要求 |
| --- | --- | --- |
| **P0** | 必须完成（本期必做） | 100% 实现并通过对应测试用例 |
| **P1** | 选做推荐（学有余力） | 实现后需补测试用例，不影响必做验收 |
| **P2** | 拓展创新 | 演示即可，不作为验收门槛 |

### 4.4 四条底线（课程要求）

> **提醒能触发、数据能显示、断电不丢设置、连续运行不死机。**

基础较弱的小组只做 P0–P3 + P4 六页面即可达标。

| --- | --- | --- | --- |
| **FR-19** | PC 端大模型健康问答 | 手环经 Wi-Fi 连入 PC 后，PC 管理端提供自然语言入口：用户用自然语言询问「最近久坐情况 / 某天步数趋势」等；PC 端把问题 + 检索片段送入**本地部署的大模型**，返回回答并**标注检索来源时间段**与「教学演示，非医疗建议」免责声明。模型选型（待补充）；不上传公网、不采集真实身份、不做诊断结论 | 选做（P2 加分） |

## 8. 状态模型（久坐状态机）

状态图见 `diagrams/P0_图集.drawio` 的「久坐状态图」页。状态迁移表（表 3-4）：

| # | 当前状态 | 事件 / 条件 | 下一状态 | 动作 |
| --- | --- | --- | --- | --- |
| 1 | `WearOff` | PPG 直流分量恢复 + 姿态稳定（检测到佩戴） | `Active` | 开始计时、记录佩戴时刻 |

## 9. 界面与页面原型

### 9.1 页面环形结构

```
表盘(根) → 运动 → 心率血氧 → 体温 → 久坐 → 设置 → 回表盘
```

- 短按按键 = 右切一页；长按 2 s = 熄屏/亮屏；长按 5 s = 回表盘。
- 必做页：**表盘、运动、久坐、设置**；未实现的选做页显示「**未启用**」而非留白。
- 切页 180 ms 淡入，切页不销毁对象。

### 9.2 信息层级（表 3-5）

| 层级 | 内容 | 规则 |
| --- | --- | --- |
| L0 常驻 | 状态栏（固定 100% 电量、同步状态）、底部页点 | 页点仅作指示，不可点 |
| L1 页面 | 单页单任务，六页面 | 切换 180 ms 淡入 |
| L2 弹窗 | 遮罩 60% 黑，仅 1–2 个动作 | 超时自动处理；未处理不许切页 |
| L3 系统 | 关机 / 恢复出厂 / OTA / **鼠标映射开关（新增选做）** | 需二次确认；恢复出厂清空 NVS 与记录；鼠标映射默认关、可一键断开 |

> 新增选做的界面落点：PC 管理端增设「健康问答面板」（问题输入 / 回答 / **RAG 检索来源卡** / 免责声明）与「鼠标映射开关面板」，手环端仅在设置页 L3 增加一个开关；三项均为选做，未实现时对应入口显示「未启用」。详见 `用户界面设计说明书_V1.0.docx`。

### 9.3 交互规范

- 可点击区 ≥ 48×48 px（约 8 mm），主按钮高 56 px，正文 18–20 px，关键数值 40–112 px。
- **颜色不单独承载信息**（例：心率红色 +「bpm」文字）。
- 关键数值必须附单位与解释（FR-17），测量状态与信号质量同显。

## 10. 数据需求（摘要，完整定义见附录 B）

### 10.1 分钟记录（16 字节小端）

| 偏移 | 字段 | 类型 | 说明 |
| --- | --- | --- | --- |
| 0 | `ts` | uint32 | Unix 秒（UTC） |
| 4 | `steps` | uint16 | 该分钟步数 |
| 6 | `hr` | uint8 | 0 = 无效 |
| 7 | `spo2` | uint8 | 0 = 无效 |
| 8 | `tempX100` | int16 | 温度以 0.01 ℃ 存整数 |
| 10 | `sitMin` | uint8 | 久坐累计分钟 |
| 11 | `flags` | uint8 | bit0 佩戴 / bit1 预留 / bit2 跌倒 |
| 12 | `reserved` | uint32 | 保留 |

### 10.2 同步协议（JSON Lines）

`AUTH` / `SYNC` / `ACK` 三类消息；错误码：0 成功、1001 设备未注册、1002 token 无效、1003 协议版本不支持、2001 记录字段缺失或类型错、2002 时间戳越界、3001 数据库忙、3002 磁盘空间不足、4001 消息超过 64 KB。

### 10.3 PC 端库表（选做）

`users` / `devices` / `records`（主键 `device_id, ts`，天然幂等）/ `events` / `sync_state`；SQLite WAL 模式。

## 附录 A：用户提供的痛点调研清单（原文归类）

> 以下 4 类为用户在 P0 导入阶段提供的调研素材，本文档 §2.2 已按 P0 要求的三个角色重组；**第 2 类「软件生态与兼容性」在 `01_角色痛点与需求映射.md` §2 做专题展开并逐条给出需求与设计对策**。

**1. 硬件体验与耐用性**：续航焦虑（续航短、需频繁充电）；发热与耐用（运行/充电发热严重、不抗摔）；屏幕问题（黑屏、闪退、卡死）；配件昂贵（充电器、维修费、整机价格偏高）。

**2. 软件生态与兼容性**：信号与连接（信号差、与手机/其他平台消息提醒有延迟、平台间互通不便）；软件适配差（国产软件匹配度差、功能比手机端少很多）；数据不准（睡眠记录不精确、大量误判，数据参考价值打折）。

**3. 功能表现与算法局限**：影像能力弱（成像模糊、抓拍差）；数据监测不准（心率受摆臂和变速影响波动大；计步受非步行动作干扰；热量估算不精准；睡眠阶段难区分）；缺乏个性化（指标多但缺解释、不知意义；固定阈值不适合所有人，未做到千人千面）。

**4. 隐私安全与功耗平衡**：隐私保护弱（资料保密性差、泄露风险）；采样与功耗矛盾（提高心率/定位等监测频率极耗电，降低频率又易遗漏关键身体变化）。

## 附录 B：AI 辅助开发说明

本文档在整理过程中使用了 AI 辅助（对应原方案附录 C）。遵守三条边界：

1. **不把 AI 当数据手册**：器件地址、寄存器、电气参数均以原方案与器件手册为准。
2. **不把 AI 当测试结论**：所有精度指标（100 步基准、45 min 误差、±5 bpm 等）均须实测，AI 不生成测试结论。
3. **不把 AI 当责任主体**：需求取舍与验收判定由小组与课程教师确认，引用 AI 生成内容在此附录说明。
