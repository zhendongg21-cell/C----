# 基于 ESP32-S3 的智能健康手环 — 第 3 组工程仓库

> 课程《智能健康手环实训》· P0 阶段基线 · 10 天 / 80 学时
> **本产品为教学原型，非医疗器械，界面须标注「非医疗用途」。**

## 一句话定位

腕戴式健康监测终端：**终端本地完成采集、判定、提醒、记录**，断网、无手机、无 App 时久坐提醒照样工作；PC 端只做事后只读归档。

核心闭环 **察觉—提醒—反馈**：连续 45 min 无有效活动且佩戴中、非免打扰时段 → 马达 2 s×3 + 全屏弹窗 → 「已起身」/「稍后 10 min」→ 走 30 步复位。

## 本期范围（P0 任务书）

| 必做 | 选做（原有） | 选做（新增 · 用户追加） |
| --- | --- | --- |
| 计步与活动强度、久坐判定与提醒、表盘、设置（阈值可调 + 掉电保存）、运动页面、传感器自检、本地记录 | 心率/血氧、体温、跌倒检测、Wi-Fi 同步、PC 管理端 | ① 连入 PC 接入**大模型健康问答**；② **RAG 检索**（语料＝PC 端已归档数据）；③ 手环**操控鼠标**（BLE HID，默认关） |

> 三项新增选做的共同前置是「Wi-Fi 同步 + PC 管理端归档」；它们挂在归档之后，裁剪任一不影响必做闭环与四条底线。详见 [`docs/00_需求规格说明书.md`](docs/00_需求规格说明书.md) §4、§5.2、§3.4。

**明确不做**：电池/充电管理、摄像头、手机 App 生态适配、睡眠分期、医学级精度、真实身份数据上公网；三项新增选做同样不上传公网、不作医疗诊断、不自研 PC 驱动内核。详见 [`docs/00_需求规格说明书.md`](docs/00_需求规格说明书.md) §4。

## 快速开始

```bash
# 工具链：ESP-IDF 5.x / CMake 3.16+ / Ninja / C++17
idf.py set-target esp32s3
idf.py build
idf.py -p <PORT> flash monitor
```

P0 阶段尚无固件代码；本仓库当前交付的是**需求基线、图集与工程骨架**。P1 起按 `feature/xxx` 分支填充 `main/` 目录。

## 四条底线

> 提醒能触发 · 数据能显示 · 断电不丢设置 · 连续运行不死机

## 关键约定

- 分支：`main` 受保护，功能走 `feature/xxx`，MR + ≥1 人评审合入
- 提交：`<type>: <动词><对象>，<原因>`，例 `fix: 修复马达震动期间误计步的问题`
- 分层红线：`ui/` 无 `i2c_master_`、`driver/` 无 `lv_`、`service/` 不直接操作 GPIO
- 数据：只采健康相关数据，不上传姓名/学号；虚构用户与模拟数据；不上传公网
- 精度指标须实测，AI 不生成测试结论
